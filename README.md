# PKMN-World-Guide

A complete strategy guide for **[Pokémon World](https://github.com/evilchinesefood/PKMN-World)**, a GBA
ROM hack built on pokeemerald-expansion that merges Kanto, Johto and Hoenn into one game.

Modelled on the printed guides of the late 90s and early 2000s — aerial maps with numbered callouts,
every hidden item marked, every trainer's full party, complete walkthroughs, boss strategy pages and
sidebars. The difference is that this site is **generated from the game's own source**, so it can be
exhaustive and stay correct across releases.

**Live: <https://dev.jdayers.com/pkmn-world/>** — CI deploys on every push to `main`.

## How it works

The game repo enters here as a read-only git submodule at `game/`, pinned to an exact commit. Python
extractors under `tools/extract/` read that source and emit deterministic JSON to `data/generated/`.
An Astro site renders those files. Nothing in `data/generated/` is ever hand-edited — if the output is
wrong, the extractor is wrong.

| Path | What it is |
| --- | --- |
| `game/` | submodule, pinned commit, read only — never modified by this repo |
| `tools/extract/` | Python extractors, one module per entity; `All.py` runs them in order |
| `tools/porymap/` | `Render.py`, the map image renderer (Porymap cannot render this project — decision 3) |
| `tools/sprites/` | `Extract.py`, species front pics, species icons and item icons |
| `tools/validate/` | `CheckCoords.py`, coordinate and manifest invariants |
| `tools/qa/` | checks over the built site: links, the departure checklist, the chapter schema, the banner's geometry in a real browser, printed PDFs |
| `tools/versions/` | `Diff.py`, what changed between game pins — reads this repo's own git history |
| `tools/mgba/` | `Capture.lua` + `Check.py`, gameplay screenshots from a ROM **you** supply; never run by CI |
| `data/generated/` | extractor output, committed |
| `data/manifest/` | `map-manifest.json` — the interface between map images and the site |
| `data/versions/` | `versions.json` — generated from git history and committed, deliberately **not** in `data/generated/` (decision 77) |
| `content/` | hand-written markdown (walkthroughs, strategy) |
| `src/` | Astro site |
| `public/maps/`, `public/sprites/` | rendered PNGs — **gitignored**, regenerated by CI (decision 13) |
| `docs/` | `NEXT.md`, `DATA-AUDIT.md`, `DECISIONS.md`, `SCHEMAS.md` |

## Building it yourself

Needs Python 3.12+ with `pillow` and `numpy`, and Node 22+ (the QA scripts import `.ts` directly and
rely on Node's type stripping).

```sh
git submodule update --init game
npm install
python3 -m pip install pillow numpy      # or a venv; see the note below
```

Then run the gate **in this order** — it is the order `.github/workflows/Deploy.yml` uses plus one
local-only step, and the extractors are order-dependent (`Gates.py` runs last inside `All.py` and
rewrites four files in place):

```sh
python3 tools/extract/All.py --check-determinism   # 8 JSON files, must be byte-stable
python3 tools/porymap/Render.py                    # 966 layouts -> 1195 map entries
python3 tools/sprites/Extract.py                   # 1,978 sprite PNGs
python3 tools/validate/CheckCoords.py              # coordinate invariants
python3 tools/versions/Diff.py --check             # versions.json is current -- LOCAL ONLY
node tools/qa/Checklist.mjs                        # 21 markdown shapes, 203 assertions
npx astro build                                    # 1,635 pages
npx pagefind                                       # search index over dist/, ~0.5s
node tools/qa/Chapters.mjs                         # the chapter `sections:` contract
node tools/qa/Links.mjs                            # 0 broken, 0 orphans, 0 unreachable
node tools/qa/Chrome.mjs                           # the banner's geometry, in Chromium
node tools/qa/Keys.mjs                             # the six frozen checklist keys
```

Sprites must be extracted **before** the build: `src/Sprites.ts` asks the filesystem whether each
sprite exists and falls back to a text-only layout when it does not, so a build with an empty
`public/sprites/` succeeds and quietly ships 1,645 fewer links than it should.

`tools/qa/Chrome.mjs` is the only step that drives a real browser. It clicks the banner's menu key
rather than setting `open`, because a key that is off-screen or covered fails a click and passes a
property set. Run `npx playwright install chromium` once if it complains; CI installs it in a step
of its own.

**`tools/versions/Diff.py` is local-only by necessity, and must not be added to CI.** It reads this
repo's git history, and `actions/checkout@v4` clones at depth 1 — on a runner the tool would find
one pin, no transition, and overwrite a real diff with an empty one that still parses and still
validates. That is exactly why `data/versions/versions.json` is committed instead of generated at
build time. A re-pin is therefore **two commits**: re-pin and re-extract in one, then run
`python3 tools/versions/Diff.py` and commit `versions.json` in a second — every byte the tool reads
comes from `git cat-file`, so it cannot see a new pin until that pin's data is committed. `--check`
is the only thing that catches a `versions.json` left stale by a forgotten second commit.

Two platform notes:

- **macOS.** Homebrew's Python is PEP 668 externally managed, so use a venv (`python3 -m venv .venv`)
  rather than `pip install` into it. `.venv/` is gitignored.
- The extractors invoke the preprocessor as `cc -E` with joined include flags. Apple's `/usr/bin/cpp`
  runs clang in *traditional* mode, where `//` is not a comment — the game's `#define X TRUE // note`
  config then carries the note into the macro body and every `#if` over it dies. See the comment on
  `cpp()` in `tools/extract/Species.py`.

## Screenshots from the emulator

`tools/mgba/` captures gameplay screenshots using mGBA's built-in Lua scripting. **It needs a ROM
and savestates that you supply** — this repository contains none and never will — and it is the one
tool here that **CI never runs**: `ubuntu-latest` has no display and no ROM.

It runs from mGBA's **Tools → Scripting** console with the ROM already open, because **no released
mGBA can load a script from the command line.** 0.10.5's `--help` offers a BIOS, cheats, a config,
a debugger, a savestate, a patch, frameskip, log levels and graphics scaling — nothing that loads a
script and nothing that runs headless. Load `tools/mgba/Capture.lua` once; it reads
`tools/mgba/shots.json` and, for each entry, opens the named savestate, advances a fixed number of
frames, writes `public/screenshots/<id>.png` and records the shot in
`public/screenshots/manifest.json`. The PNGs are gitignored, the manifest is committed. A fixed
savestate plus a fixed frame count is the **only** thing making a capture reproducible — anything the
game animates on a timer or an RNG still differs between runs.

`python3 tools/mgba/Check.py` validates the shot list — unique ids, id shape, savestate present,
frame count a positive integer, no two shots colliding on one output path — and is the only part of
this that can be checked without a ROM. **Nothing in `tools/mgba/` has ever been executed inside
mGBA.** Its behaviour is established by reading mGBA 0.10.5's own source, and `Capture.lua`'s header
distinguishes what is a citation from what was actually tested. Decision 79.
